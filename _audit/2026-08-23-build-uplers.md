**ITEM ZERO: uplers did NOT have naukri's defect, and had three others.** The sweep's `SECRETS` holds the JWT strings themselves, so a whole-token echo always fired. Measured blind instead: (1) one base64url **segment** alone - `token.split(".")[1]` is not a superstring of the token, yet it decodes to the entire identity half; (2) **decoded claims**, which is not hypothetical because `token_expiry` already decodes that segment - that one IS naukri's failure transposed; (3) the `secret[:12]` clause was matching a **constant** - `eyJhbGciOiJI`, the standard HS256 header, identical across all three JWTs, so zero credential-specific signal plus three false fires on prose describing a JWT. And the only control planted a **Sanctum** token, a format that wears its secret in the clear, so the JWT arm was certified by nothing. Replaced with a per-credential fragment set (whole value, each segment, decoded claims, sanctum tail) minus the fragments of a **format decoy**, so the header is subtracted by measurement rather than by hand. **Reverting to the old rule turns 4 of the 5 new controls red**; the plaintext and whole-JWT controls stay green, which is exactly the point. Same detector now backs the JWT arm in `test_session.py` and `test_talent_tools.py`.
